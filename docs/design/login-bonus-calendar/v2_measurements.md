# ログインボーナスのカレンダー表示 V2 の基準実測

> **この実測の注意（PR 本文に転記できる）**: 測ったのは「未ログインの状態の login_bonus・home を単独起動」したときのデバイス非依存の指標だけです（実サーバーを通した通しは、ローカルのサーバーが旧スキーマで login が 500 のため不可）。最大構成（通常 7＋VIP 7＋報酬 5 行）は V3 の前で未測定、実機（iPhone X）の 60fps も未測定です。ホームのドロー呼び出しが 31 → 28 に減った理由は断定できません。V3 の後の比較では、この増減を実装の効果と読まないでください。

`client_design.md` の 7 節（60fps の指標）と 5-6 節（APK 容量 R4）の、V2 時点の実測値。V3（カレンダー・スタンプ）の後に同じ手順で測り直して比べる。**実機（iPhone X）での 60fps は未確認**（書き出しテンプレートが無く、この環境では測れない）。

## 60fps の指標（R2）

- 手順: `debug/frame_probe.gd` を `--e2e-frame-probe=<秒>`（`debug/e2e_driver.gd`）で起動し、画面が出てから 2 秒間（約 105 フレーム）の `TIME_PROCESS`・ドロー呼び出し・オブジェクト数・ノード数の平均・最大を `E2E_PROBE:` の行に出す。**ヘッドレスでは描画統計が 0 になるので、ウィンドウありの通常起動で測った**（macOS・Metal・Forward Mobile。ヘッドレスのときは行に `render=unavailable(headless)` が付く）
- 測った画面: `login_bonus.tscn` と `home.tscn` を単独で起動（`godot --path . res://contexts/.../xxx.tscn -- --e2e-case=probe --e2e-frame-probe=2`）。**ローカルのサーバーが旧スキーマのまま（login が 500 を返す）で、実サーバーを通した通しの起動ができなかったため、未ログインの状態（ログインボーナスは受取なし・ホームの値は「-」）で測った**。ドロー呼び出し・オブジェクト数・ノード数は端末に依らない指標なので、変更前後の比には使える。`TIME_PROCESS` は開発機の値で、背景動画のデコードに支配されて 21〜41ms とばらつく（絶対値には使わない）
- 変更前の基準（main）と、V2 の後（ホームの値の横のアイコン 3 つを足した状態）:

| 画面 | 状態 | ドロー呼び出し（平均 / 最大） | オブジェクト数 | ノード数 | `TIME_PROCESS` ms（平均。ばらつく） |
| --- | --- | --- | --- | --- | --- |
| ログインボーナス（現行の文字の画面） | 変更前 = V2 後（V2 では変えない） | 12.88 / 13 | 80.2 / 81 | 29 | 24〜33 |
| ホーム | 変更前（3 回） | 30.7 / 31 | 72.3 / 73 | 46 | 27.6〜30.7 |
| ホーム | V2 後（3 回） | 27.7 / 28 | 69.3 / 70 | 52 | 32.2〜34.3 |

- 読み: ホームはノードが 46 → 52（`ValueRow` 3 つ + `ItemIcon` 3 つ）。ドロー呼び出し・オブジェクト数は**増えていない**（31 → 28、73 → 70。同じ手順を変更前・後で 3 回ずつ測って再現した。アイコンを足して減るのは直感に反するため、理由は断定しない）。`TIME_PROCESS` は +5ms ほどに見えるが、動画のデコードに支配されたばらつきの範囲（同じ状態でも 21〜41ms）で、判断には使わない
- 切り分け（1 回）: V2 後の構成で `ItemIcon` の `texture` を一時的に設定しないで測ると、ドロー呼び出し 24.8 / オブジェクト 66.4 / ノード 52（2 回とも同じ）。つまり絵を出すと +3 ドロー・+3 オブジェクト（アイコン 1 つにつき 1。直感どおり）で、変更前（31 / 73）より減っているのは**アイコンの有無ではなく、値ラベルを `HBoxContainer`（`ValueRow`）で包んだレイアウトの変更側**にある（なぜ減るかは未調査）。**V3 の後の比較では、ホームの増減を実装の効果と読まず、同じ画面の同じ構成どうしで比べる**
- **未測定**: 最大構成（通常 7 + VIP 7 + 報酬 5 行）の変更後の値は、カレンダー（V3）がまだ無いので測れない。V3 の後に同じ手順で測り、ドロー呼び出し・オブジェクト数が基準（ログインボーナス 12.88 / 80.2）の何倍かを書く

## APK 容量（R4）

`docs/ASSETS.md` の「アイコン（自作）」の「容量の実測」の表を参照（比較用の 3 点の時点と全 40 点の時点の 2 回）。結果: 全 40 点で SVG 41,792 B・import 後 155,552 B・pck の差 176,660 B で、基準（1MB 以内かつ背景動画 2,028,637 B 以内）を満たす。なお比較用の 3 点の時点の pck の差は、製品用の複製ではなくリポジトリ全体の複製で測った（アイコンあり・なしの差だけを見るので値は同等）。
